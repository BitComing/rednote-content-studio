# 校园商家小红书内容工作台 · 2026-11-19 改造版

本项目保留两个 Dify 应用：首轮生成、分支改稿。前端真实调用两个不同的应用密钥；审核和版本管理在前端与服务端完成，不再依赖 Dify Human 节点暂停。

## 先运行页面

```powershell
npm install
npm run dev -- --hostname 127.0.0.1
```

未配置首轮 Dify 密钥时仅运行交互演示：使用输入简报展示操作，**不伪造生成文案、评分、热度或审核通过**。真实模式失败时直接显示错误，不自动退回演示。演示任务接入密钥后仍保持演示属性，请新建首轮任务。

## 导入两份新版工作流

项目上两级目录 `Project_Upgrade_20261119` 中有：

- `首轮_可复用生成工具_v2.yaml` / `.ifpkg`
- `改稿_分支与首轮复用_v2.yaml` / `.ifpkg`

按实例的导入界面选 YAML 或应用包。原来两个“课程项目”文件夹内的 `app.yaml`、`manifest.yaml` 以及同名 ZIP 也已同步更新。修改前原稿另存为 `original_first.yaml` 和 `original_revision.yaml`。

1. 导入首轮，检查并配置模型供应商，发布，获得**首轮应用 Key**。模型保留原文件的 DeepSeek 配置，需要你的账户有对应模型权限。
2. 导入改稿，在 Dify 环境变量设置 `FIRST_ROUND_API_BASE=https://api.dify.ai/v1`（不要末尾斜杠）和秘密变量 `FIRST_ROUND_API_KEY=首轮应用的 Key`。这个 Key 不能填写改稿应用自己的，否则会产生错误调用。
3. 发布改稿应用，获得**改稿应用 Key**。
4. 前端右上角 Dify 设置分别填写两枚 Key，也可复制 `.env.example` 为 `.env.local` 填写 `DIFY_API_KEY`、`DIFY_REVISION_API_KEY`。
5. 页面设置的 Base URL、首轮 Key 优先于环境变量；改稿 Key 优先使用已保存页面值，其次使用环境变量。设置文件实际是本项目 `.data/dify-config.json`，不会返回明文密钥给浏览器。连接测试当前只测首轮 `/info`；改稿及首轮复用以实际运行验证。

“重新生成”分支通过 Dify HTTP 节点调用已发布首轮 API，包含真正的跨工作流复用。首轮不重复内嵌到第二轮。**这不等于已经绑定了你工作区的原生 Workflow Tool 节点。** 若课程要求展示原生工具节点，见交付目录的《改造分析与配置说明》中绑定步骤；工作区工具 ID 必须在你的 Dify 中产生，文件不包含假 ID。

## 配置独立评估

在 `.env.local` 中填写并重启：

```dotenv
EVAL_BASE_URL=https://你的模型服务/v1
EVAL_API_KEY=你的服务密钥
EVAL_MODELS=模型A的实际ID,模型B的实际ID
GENERATION_MODEL=deepseek-v4-flash
```

评估接口使用 OpenAI 兼容 `POST /chat/completions` 格式，服务需支持 `messages`、`temperature` 和文本 JSON 回答。最多并发三个不同模型 ID；建议选两个不同模型家族，并与生成模型不同。若使用不同供应商，可通过支持这些模型的统一服务接入。`EVAL_MODELS` 中的 ID 必须是该服务实际提供的名称，不要直接使用“模型A”。没有配置真实 Key 时不会调用或伪造外部评分。

采用**初稿和每版修改稿分开评估**。每个评估者看当前内容、事实材料和目标，不看旧分数。事实40%、风险25%、校园与平台适配15%、语气10%、清晰度10%；每项0–5分，总分由服务端计算。展示各模型分项理由、均分、最大分差、耗时。任何模型提出阻断风险、分差超过15分、评估失败或不足两个成功模型时，暂不能确认通过。外部评估是辅助证据，不是自动发布授权。

内部 Dify 评审仍保留原有整包分数和规则检查；它不是外部模型均分，也不是每个平台独立评分。

## 改稿方式

| 选择 | 实际动作 | 跳过的工作 |
|---|---|---|
| 自动 | 事实补充优先；仅换 tone → tone；只有评分异议 → 复评；混合意见 → 局部修改 | 不调用额外 LLM 猜分支 |
| 只调整语气 | 独立轻量编辑节点，以当前稿为底稿，要求冻结事实、结构和数字 | 不重提取资料、不重新分析平台 |
| 局部内容 / 话题 | 修改受影响段落，尽量保留其余原文 | 不重跑首轮 |
| 纠正事实 | 根据明确的已核实纠正修改所有受影响位置 | 不重跑首轮 |
| 仅重新评分 | 原文逐字不变，只评审 | 不调用改写模型 |
| 重新生成 | 第二轮调用首轮完整工具 API，复用已提取资料 | 不重新上传文档，也不重复执行第二轮内部评审 |

每次都对处理后的文案重新做风险检查与外部评估。可以提交 V2、V3、V4……，没有写死只允许两轮，也没有自动无限重试；每次由人点击，受输入长度、服务额度和超时约束。后续使用**最新稿件、最新 tone、累计已核实纠正和原始简报快照**。左侧在首轮后修改简报不影响当前任务，要改变活动基础设定请重新运行首轮。

改稿和归档使用服务端保存的任务与版本，不相信浏览器回传的稿件/通过标记。旧版本提交会被拒绝，防止并行请求覆盖。刷新页面恢复最近任务。所有版本及模型评估可以导出 JSON；Markdown 导出的是当前稿，标有任务状态。

## 校园场景与知识库

默认只选小红书，仍保留其他平台兼容能力。四个场景：日常门店、考试周、社团活动/市集、迎新。

- `src/lib/campus.ts`：项目内部写作指引，不能作为优惠、校方背书等事实依据。
- `data/merchant-knowledge.json`：商家事实库，初始为空。
- `data/merchant-knowledge.example.json`：填写模板，不会自动进入实际库。

真实材料经商家确认后写入实际库，填写商家编号、适用场景、原文、材料来源、确认日期及失效日期，并将 `verified` 设为 `true`。页面输入匹配的商家编号。检索按商家、场景、已核实和有效期过滤，最多返回8条，首次生成时固定快照，以便复现。没有匹配资料时只使用简报和上传文档，不跨商家借用事实。

这是**本地结构化资料检索**，不是声称已经部署 Dify 向量知识库。它适合课程小规模资料，后续可迁移 Dify 知识检索并保留商家隔离、时间过滤和引用。不得把知识库模板、合成测试数据或编辑规则当作真实需求调研。

热点按钮实际请求第三方微博热榜。加载失败返回空列表，可不附加热点继续；不显示预设热度。它不是小红书官方热榜。图片仅随文件流传入，当前工作流不识别图片里的价格或资质，请转写关键事实。

## 运行边界

目前是本地单人课程原型，没有账户登录、多人权限、支付、排期和自动发布。请用本机地址运行；不要直接暴露配置接口到公网。`.data` 包含商家资料和运行记录，源代码包已排除这些数据和密钥。若进程异常退出留下 `.data/runs/任务ID.json.lock`，先确认该任务已无运行请求，再删除对应锁文件。

本次验证包括编译、本地逻辑测试、接口模拟和页面交互；不等于已经完成你 Dify 工作区的导入、发布、真实模型运行或商家验收。
